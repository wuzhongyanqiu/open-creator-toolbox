# 全工作区游戏视觉资产工作流

更新日期：2026-10-18

本规范服务于所有游戏仓库及操作它们的 Agent，包括 DeepSeek Harness、Codex、Devin。入口在工作区根 `AGENTS.md`；工具索引见 [GAME_DEV_TOOLKIT.md](GAME_DEV_TOOLKIT.md)，资产登记与许可见 [GAME_ASSET_PIPELINE.md](GAME_ASSET_PIPELINE.md)。

## 生图：SRI Image 2.5

用户指定的新图与图像编辑默认使用 SRI 的 **Image 2.5**，不继续沿用旧脚本默认的 `gpt-image-1` 或旧文档中的 FLUX 主链。既有资产无需仅因模型变更批量重生成。

| 用途 | SRI API 模型 ID | 选择原则 |
| --- | --- | --- |
| 正式候选资产、复杂角色与场景、精细修改 | `gpt-image-2.5-sunburst` | 默认；先生成少量样图定风格，再扩充同系列 |
| 构图探索与批量草稿 | `gpt-image-2.5-flare` | 可用于草稿；正式采用前仍需实机审查 |

以上两个 ID 于 2026-10-18 从 SRI `GET /v1/models` 实测确认。这里只确认模型目录存在，未在此次文档任务中验证两者的全部参数、参考图或透明背景能力；不得把旧模型的参数支持情况直接套用。再次使用前检查实时目录、脚本与请求响应；遇到不可用或参数错误，记录失败并修正，不静默换成旧模型。

- API 根：`https://sri-ai.xyz/v1`。现有脚本通过 `POST /images/generations` 生图，带参考图的编辑通过 `/images/edits`；SRI 兼容格式以当前脚本与实测响应为准。
- 凭据：现有各仓库 `scripts/gen-images.mjs` 从 `~/.codex/auth.json` 的 `OPENAI_API_KEY` 读取 SRI Key。只由本地进程读取并用于 SRI 请求，禁止 `cat` 整份凭据、输出认证头、把 Key 写进提示词/源码/报告/提交，或发给其他供应商。环境注入仅在对应脚本明确支持时使用。
- 先检查脚本：有些旧脚本仍默认 `gpt-image-1`，调用时显式指定 `--model gpt-image-2.5-sunburst`；若没有模型选项，在所属仓库按规范修改脚本后再生成。不要把文档变更描述为已经升级了所有项目脚本。
- 检查 `IMAGE_API_BASE` 等覆盖值确实指向 SRI，再加载凭据。使用系统代理时复用脚本的代理检测；此次目录查询需要现有脚本使用的 User-Agent/代理方式，裸请求失败不能直接判定模型不存在。
- 记录提示词、参考资产路径、模型 ID、用途、生成时间、输出哈希与处理步骤；沿用 `docs/ART_PROMPTS.jsonl` 和项目的资产清单。参考图必须有使用权。
- 风格先行：固定视角、比例、轮廓、材质、光向和色板；地图模块、角色、敌人及状态变体共用风格说明与参考图。图中的文字优先由游戏 UI 绘制。

支持该参数的现有脚本调用示例（不含密钥）：

```bash
node scripts/gen-images.mjs <manifest.jsonl> --model gpt-image-2.5-sunburst --jobs 1
```

## 建模：Blender 为主，Tripo 生成草模

- 主工具：本机 `/opt/homebrew/bin/blender`；2026-10-18 实测为 Blender 5.2.2 LTS。可以用 `blender -b -P <script.py>` 离线建模、摆场景、绑定、动画和渲染。CLI 已可用不代表 Blender MCP 插件已经安装或连接。
- **Tripo**：云端文生/图生 3D 服务，用于角色、敌人、建筑和环境道具的候选草模。参考 [Tripo 官方入门](https://developers.tripo3d.ai/en/docs/quick-start) 和 [接口目录](https://developers.tripo3d.ai/en/docs/introduction)。需要独立账号、额度和 `TRIPO_API_KEY`；SRI Key 与 OpenRouter Key 都不能替代。此次没有验证 Tripo 账号、API 凭据、额度或本机集成，不得宣称已接通。
- Tripo 请求是异步任务：使用当前文档的匹配 API 版本和模型参数，保存任务 ID、模型版本、输入来源、输出与许可依据。不要混用不同版本教程中的地址与字段。仅在已有账号/额度和授权范围内调用，不自动购买套餐。
- **TripoSR**：开源图生 3D 工具，与 Tripo 云服务不同；[模型卡](https://huggingface.co/stabilityai/TripoSR) 标明 MIT，仍要登记参考图来源与生成过程。TRELLIS.2 也可作为已有流程中的草模备选；本机可用性需另外实测。
- 草模进入 Blender 后做轮廓检查、重拓扑/减面、UV、材质统一、尺寸与朝向校准；角色补绑定和动作，配置碰撞、LOD、图集或实例化，并验证导出结果。不能仅导入高面数生成物就视为完成。
- 3D 运行时优先导出项目支持的 GLB；2D/Phaser/DOM 游戏可以离线渲染为透明精灵、方向帧或背景模块，保持已有技术栈。透明处理须检查边缘、阴影与实际背景融合。
- Tripo 云服务按使用时的套餐、API 条款和资产授权逐项核对，归 `verify`；不能套用 TripoSR 的 MIT，也不能默认免费产物可商用。无可用凭据时继续使用 Blender 制作并如实报告。

## 审图与游戏内验收

Image 2.5 负责生成图，DeepSeek 1017 等视觉模型负责结合实际玩法审图，Blender 负责 3D 资产制作与处理。三者职责不同。

1. 先看当前实机和内容数据，记录地图可玩面积、地形/关卡主题、角色/兵种数量、无尽模式变化和当前缺陷，确定每款游戏的扩充方向。
2. 先做一套连贯的样例场景、角色和状态反馈，在游戏中验证，再批量生成/建模。不要仅拉伸地图、重复贴图或叠加粒子冒充内容扩展。
3. 将新资产接入游戏，对照修改前后的真实截图，检查美术一致性、视觉层级、目标辨识、文字与按钮可读性、遮挡、动画节奏和操作反馈。地图变大后同时检查镜头、寻路、触控与导航。
4. 移动端至少在 390×844、360×640 跑关键路径并检查小字、横向溢出、安全区；战斗/无尽模式检查后期单位密度与特效性能、失败重试及存档兼容。需要真机而未完成的部分单独报告。
5. 看图时一次 1–3 张关键截图；大量画面先做细节可辨的联系图，记录文字结论与原图路径。避免把几十张历史截图反复塞进同一请求；2 MiB 图片字节预算不等于严格的 30 张数量限制，必要时分批或压缩上下文。
6. 每个仓库独立运行适用的检查，审查差异后只提交本任务文件，向已配置的自有发布远端推送并核对。TapTap 上传、提审、上线沿用用户当前指示，不能把资产验收视为发布授权。
