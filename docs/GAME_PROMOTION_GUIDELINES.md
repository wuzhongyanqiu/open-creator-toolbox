# 游戏宣发与话题标签规范

记录日期：2026-10-23。来源：用户明确要求“之后宣发统一都要标注 tag”“宣发游戏的时候一定要打 tag，可以参考其他的帖子”。这是长期要求，适用于所有游戏、平台与执行者（包括 Codex、DeepSeek Harness、Devin 及人工协作者）。

## 必须执行

1. 每篇游戏宣发必须带相关 tag / 话题标签，包括首次宣传、版本更新、开发日志、实机图文和宣发视频。论坛归属、分类、正文关键词、AI 生成声明均不能替代话题标签。
2. 写稿前查看目标平台同类或同游戏的近期帖子，了解真实话题名称与用法；只借鉴标签和表达结构，不抄袭正文，不添加与游戏无关的热门话题。
3. 平台有原生“添加话题”功能时，搜索并选中实际话题，使帖子形成可点击的话题关联。没有原生功能的平台，按该平台支持的 hashtag 语法填写。不得凭空宣称不存在的话题已添加成功。
4. 发布前检查标题、版本状态、玩法事实、配图与标签；发布后回到帖子页面，确认正文、图片与 tag 都显示成功，保存链接及标签名称。只填进编辑器或只保存草稿不能描述为已发布。
5. 用户要求“上线后发”的更新帖，必须先核对对应新版的上线状态与包体身份；审核中、已上传、旧版仍在线都不等于新版已上线。尚未上线时先保存完整文案和候选标签，后续只发布一次。

## 标签选择建议

按内容组合少量相关话题，通常 3—5 个即可，具体以平台限制和实际可选话题为准：

- 游戏名：平台存在对应话题时优先选择。
- 核心品类：例如模拟经营、休闲游戏、独立游戏；以玩法真实属性为准。
- 本次主题：例如游戏更新、开发日志、美食、实机演示；必须与帖子内容相符。
- 活动话题：只有游戏确实符合活动规则时才添加，不能为了流量误导归类。

以上只是候选方向，不代表平台已存在这些名称。发布时必须通过实际页面核对。游戏视觉中出现 AI 生成素材时按平台要求单独声明，AI 声明不抵扣话题标签。

## 项目内留档

在对应游戏仓库保存宣发文案或记录（例如 `docs/PROMOTION.md`），至少记下：游戏与版本、上线核验依据、标题正文、选用 tag、参考帖子链接、配图路径、发布状态、发布时间及帖子链接。临时截图放忽略的 `output/`，不提交登录信息、Cookie 或其他凭据。

工作区根 `AGENTS.md` 是所有执行者的必读入口；本文件承载具体操作步骤。视频制作仍需遵循 [游戏宣发视频工作流](GAME_PROMO_VIDEO_PIPELINE.md)。
